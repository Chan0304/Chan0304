## How projects are documented
Maintained repositories use a structured README with a project overview, scope and requirements, technical documentation guidance, delivery lifecycle, current status, and project checklist. Related prototypes and iterations are identified as companion work instead of being counted as separate production releases.

## Delivery and evidence standards
A repository is not, by itself, evidence of production readiness or client delivery. Project claims should be supported by implementation, tests, approved screenshots, architecture diagrams, deployment records, acceptance evidence, and verified outcomes. Confidential project details remain in private repositories and are not reproduced in this public profile.

## Engineering and project practices
- Requirements and acceptance criteria before delivery commitments.
- Incremental implementation with traceable commits and pull requests.
- Security, privacy, and environment-secret hygiene.
- Testing and release validation before production claims.
- Clear handover notes, risks, known limitations, and ownership.
